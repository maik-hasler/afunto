== Architecture Decisions

The following table lists the relevant architecture decisions. Each decision links to the corresponding ADR with full context, rationale, and considered alternatives.

.Architecture Decisions
[cols="1,4,8,3,3,3" options="header"]
|===
|No. |Context |Description |Status |Date |ADR

|1
|Monorepo
|Manage all components in a single repository.
|Accepted
|2026-03-23
|link:ADRs/1_monorepository.html[Monorepo]

|2
|arc42
|Use arc42 as the template for architecture documentation.
|Accepted
|2026-03-25
|link:ADRs/2_arc42.html[arc42]

|3
|Keycloak
|Use Keycloak as the Identity and Access Management solution.
|Accepted
|2026-03-25
|link:ADRs/3_keycloak.html[Keycloak]

|4
|Geocoding
|Geocode addresses at write time via Nominatim; spatial filtering by bounding box plus in-memory Haversine (no PostGIS).
|Accepted
|2026-05-13
|link:ADRs/4_geocoding_and_geo_search.html[Geocoding]

|5
|Map/geocoding proxying
|Proxy OpenStreetMap tile and Nominatim requests through the backend so visitor IP addresses are never sent to these third parties directly.
|Accepted
|2026-07-27
|link:ADRs/5_map_and_geocoding_request_proxying.html[Proxying]

|6
|Light-only theme
|Stay light-only for now; `color-scheme: light` is a deliberate, recorded decision rather than an unreviewed default.
|Accepted
|2026-08-25
|link:ADRs/6_light_only_theme.html[Light-only theme]

|7
|Repository scope
|Stop this repository's scope at building and publishing container images; deployment, staging/production and observability now live in a separate private repository.
|Accepted
|2026-08-22
|link:ADRs/7_repository_scope_stops_at_image_publishing.html[Repository scope]

|8
|Distributed tracing (historical)
|Add Grafana Tempo tracing to the (since-removed) deployed observability stack. Originally ADR-6; restored 2026-08-26 after being deleted instead of superseded - see ADR-7.
|Superseded by ADR-7
|2026-07-29
|link:ADRs/8_distributed_tracing_via_tempo.html[Distributed tracing]

|9
|Server state
|Hold server state in a TanStack Query cache instead of per-component `useEffect` + `useState`, with one place where query keys are spelled.
|Accepted
|2026-09-21
|link:ADRs/9_server_state_with_tanstack_query.html[Server state]

|10
|Frontend API client
|Generate the frontend's TypeScript client with `@hey-api/openapi-ts`; NSwag keeps generating the OpenAPI document and the integration tests' C# client.
|Accepted
|2026-09-21
|link:ADRs/10_frontend_api_client_generated_by_hey_api.html[Frontend API client]

|11
|Enforced frontend rules
|Encode the frontend's layering, its browser-global surface, its module graph and its byte budgets as CI checks rather than conventions.
|Accepted
|2026-09-21
|link:ADRs/11_frontend_architecture_rules_are_enforced.html[Enforced frontend rules]

|12
|Mobile
|Keep the PWA as the mobile story until App Store presence or guaranteed push reach is a stated need; take only the portability measures that pay for themselves on the web.
|Accepted
|2026-09-21
|link:ADRs/12_mobile_stays_a_pwa_until_distribution_demands_otherwise.html[Mobile]

|13
|Object storage
|Run RustFS instead of MinIO, reach it through AWSSDK.S3, keep the URL scheme, and pin the storage contract in integration tests.
|Accepted
|2026-10-02
|link:ADRs/13_object_storage_on_rustfs.html[Object storage]

|===

See <<section-solution-strategy>> for how the key decisions map to the quality goals.
